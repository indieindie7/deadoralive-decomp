Arcade game Dead or Alive (Tecmo, 1996) on the Sega Model 2A board: main CPU Intel i960 KB (little-endian, 32-bit), program ROM at 0x0-0xfffff (all code runs from ROM; no fast-RAM copy). Research only. Game: 3D one-on-one fighter (strikes, throws, counter-holds against high/mid/low strikes, danger zone ring edges that launch fighters, juggles, rounds, KO, time-out, character select, continue, ranking/name entry, attract demo, service/test menus, backup settings). The Sega Saturn port of this game was already named; use fighting-game module names: fight_, fighter_, move_, hit_, hold_, throw_, ai_, cam_, hud_, charsel_, round_, attract_.
Hardware (from the public MAME model2 driver): 0x800000 geo / 0x804000 TGP FIFO (geometry coprocessor: matrices, polygons and lights are sent as command words), 0x880000 copro, 0x900000 bufferram, 0x980000 video control, 0xe00000 CPU control, 0xe80000 IRQ request/enable, 0xf00000 timers, 0x1000000 tilemap (text/2D layers), 0x1800000 palette, 0x1810000 colour translation, 0x181c000 z-clip, 0x1a00000 comm board (linked cabinets), 0x1c00000 I/O (steering, throttle, brake, buttons, coins, lamps, sound commands), 0x1c80000 UART, 0x1d00000 backup SRAM, 0x2000000+ data ROM, 0x10000000+ render mode / polygon count. Work RAM is 0x500000-0x5fffff.

Task: name functions from the Ghidra decompile. FILE holds the decompile of a slice of the functions. Name EVERY function in FILE whose name is still FUN_xxxxxxxx (skip ones that already have a name).

Evidence to use: strings, called functions, hardware addresses, float maths (vectors, matrices, sin/cos, sqrt), command words pushed to the TGP FIFO, the loops and constants. Ghidra's i960 decompile is rough (register-window calls, globals as DAT_ / _DAT_); infer what the code does from its data flow. Give descriptive names; do not invent SDK names (there is no public SDK).

Naming style: lowercase module prefix + CamelCase verb, e.g. tgp_SendMatrix, geo_DrawModel, pal_SetColour, tile_PrintString, io_ReadSteering, snd_SendCommand, comm_SendPacket, irq_VBlank, fighter_UpdateState, hit_TestSpheres, hold_CheckCounter, ai_PickMove, cam_Follow, round_CheckKO, charsel_Update, test_ServiceMenu, backup_Load, math_Sqrt, vec_Normalize, mat_Multiply, mem_Copy, str_Format. Tiny stubs that only return: stub_<addr>. Data mistaken for code: data_<addr>. When unsure, still give the best descriptive name and add "provisional" at the start of the comment.

Output: write lines to OUT (create it with Write; one line per function, no other text):
0x<addr> func <name> hand <comment of 5-20 words: what it does, key callees, hardware or strings>
Addresses as 8 lowercase hex digits (e.g. 0x0003c9e0). Names must be unique within OUT; append _2, _3 when two functions would share a name. Do not read files other than FILE. Read FILE in pieces (offset/limit, about 600 lines at a time) until the end. Reply at the end with only the line count.
